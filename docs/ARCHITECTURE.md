# Architecture

This project follows a layered architecture to maintain clear boundaries and separation of concerns.

## Layers
1. **UI**: Components that handle user interaction and rendering. Never calls `fetch` directly.
2. **Hooks**: React hooks for data fetching and state management (e.g., TanStack Query).
3. **Services**: Domain-specific logic, interacting with HTTP clients, mapping data.
4. **HTTP Client**: Wrappers around `axios` or `fetch` for raw network requests.

## Key Decisions

### Unified Doc Registry
The app supports both React (`index.tsx`) and raw HTML (`index.html`) docs.
All docs are placed inside `src/docs/<slug>/` with a `meta.ts` file describing them.
`import.meta.glob` is used for eager discovery of `meta.ts` and lazy loading of doc content.

### Iframe Sandbox for HTML Docs
To prevent external HTML/JS (generated by agents) from breaking the main React app or accessing its state, HTML docs are rendered inside a sandboxed `iframe`.
- **Trade-offs**: Isolation ensures stability and security, but makes styling harder to inherit directly from the app (though we can inject theme variables).

### LeetCode Provider
LeetCode has no official CORS-friendly public API. We use an interface-based provider approach:
- Default: A community API adapter (e.g., `alfa-leetcode-api` hosted instances).
- Optional: A serverless proxy (Vercel/Netlify function) included in `api/`.
This allows easy switching if one method fails.

### Config over Code
All personal information, feature flags, and environment specific settings are in `src/config/`.
